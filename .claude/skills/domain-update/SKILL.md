# /domain-update [모드]

`we-init`이 최초로 만든 도메인 분석 번들(`docs/domain/index.md`·`docs/domain/modules/<slug>.md`·`docs/domain/domains/<slug>.md`·`docs/domain/common.md`·`docs/domain/tables/`)을 **소스 변경에 맞춰 다시 분석하거나 색인만 다시 짠다.** 카탈로그 스캔·`domain-sync` 병합·티어링·fan-out·페이지 합성의 상세 절차는 이 스킬이 다시 정의하지 않고 `.claude/docs/domain-synthesis.md`(공유 절차 문서)를 그대로 따른다 — 이 스킬은 그 절차를 **언제·얼마나(모드별 fan-out 범위)** 돌릴지만 정의한다.

## 사전 조건

- `.claude/docs/domain/index.md`가 이미 있어야 한다(=`we-init`이 도메인 번들을 만든 프로젝트). 없으면 "도메인 번들이 아직 없습니다. 먼저 `we-init`을 실행해 주세요."라 안내하고 중단한다.
- `.we-adp/composition.yaml`에서 확정된 `lang`·`frameworks` 값을 읽는다. 이 스킬은 언어·프레임워크를 다시 묻거나 재감지하지 않는다 — 최초 `we-init`이 확정한 값을 그대로 재사용한다.
- 번들이 구버전(모듈 페이지에 `## 카탈로그` 표가 없음)이어도 대상이다 — 아래 "v1 이행" 절이 처리한다.

## 모드 선택

인자로 모드를 받는다. 인자가 없으면 **증분**을 기본값으로 쓴다(가장 흔한 사용 패턴 — 소스 몇 개 바뀐 뒤 최신화).

- **전체** — 도메인 티어 모듈 전부를 처음부터 다시 fan-out 한다. 티어 판정 자체가 크게 바뀌었을 때(모듈 구조 개편 등) 쓴다.
- **증분**(기본) — 구조 재동기화는 항상 하되, 의미 빈칸이 남은 모듈만 다시 fan-out 한다. 평소 최신화는 이 모드로 충분하다.
- **재색인만** — 구조 재동기화(카탈로그·`tables/`·원장)는 그대로 하되, LLM 재저작(fan-out)은 절대 하지 않는다. 페이지를 손으로 고친 뒤 색인·집계만 맞추고 싶을 때 쓴다.

## 공통 절차 (세 모드 모두 이 순서로 시작)

`.claude/docs/domain-synthesis.md`가 정의하는 절차를 그대로 따른다. 모드별 차이는 **③의 fan-out 범위**(그리고 재색인 모드는 ③ 자체를 건너뜀)뿐이다.

```
① we-adp analyze-structure {root} --packs {lang-id,fw-id,...} --format catalog --out .we-adp/structure-catalog.json
   → 후보(candidates[]) 있으면 확정(아래 "① 후보 확정")
①.5 코드 그래프 재색인(조건부 — codebase-memory-mcp 있을 때만): 아래 "①.5 그래프 재색인" 참고
② we-adp domain-sync {root} --packs {ids}     (초회 — 카탈로그를 페이지에 결정론 반영, 의미·본문 보존)
③ 의미 빈칸 행이 있는 모듈만 fan-out (전체 모드는 전 도메인 티어 모듈 — 아래 "전체 모드" 참고)
④ we-adp domain-sync {root} --packs {ids}     (재실행 — frontmatter domain 반영 → index·domains 블록 완성)
⑤ we-adp verify-domain-rules {root}
⑥ 검수(1회·자동) — domain-synthesis.md ⑦ 그대로(분류 정합·빈칸 재도전·잘린 설명·고아 도메인 + 정착 재실행 1회)
```

`{lang-id,fw-id,...}`는 `.we-adp/composition.yaml`의 `lang`+`frameworks` 값을 그대로 옮긴 것이다.

### ① 카탈로그 스캔 + 후보 확정

①을 실행한 뒤 결과 JSON의 `candidates[]`가 비어 있지 않으면, 후보 확정은 `.claude/docs/domain-synthesis.md` ② 절차 그대로 따른다(질문 문구·`project.yaml` 기록·① 재스캔 포함 — `we-init` 1.5단계와 같은 방식이다. 여기 다시 옮겨 적지 않는다).

### ①.5 그래프 재색인 (조건부 — codebase-memory-mcp)

`.claude/docs/domain-synthesis.md` ①.5 절차 그대로다 — 세부는 그 문서를 따르고, 여기선 **모드별로 얼마나 재색인할지**만 정한다. codebase-memory-mcp 도구가 이 세션에서 잡힐 때만 수행한다(안 잡히면 조용히 건너뛰고 스켈레톤 흐름으로 폴백 — 무해). 이 프로젝트는 이미 `we-init` 이 최초 색인했으므로(전제 조건), 갱신은 **증분**이 기본이다:

- **증분·재색인만 모드**: `detect_changes` 로 지난 색인 이후 바뀐 파일만 잡아 **증분 재색인**한다. 풀 재색인하지 않는다 — 여기가 갱신 효율의 핵심(첫 색인만 무겁고 이후는 싸다).
- **전체 모드**: 모듈 구조가 크게 바뀌었을 때 쓰므로, `detect_changes` 가 광범위 변경을 보고하거나 판단상 필요하면 `index_repository` 로 **풀 재색인**한다.

그래프가 최신이면 ③ fan-out 이 `trace_path`·`query_graph` 로 흐름을 깊게 판다(`domain-synthesis.md` ④ "그래프 증강").

> **⚠ "재색인" 두 가지 — 헷갈리지 말 것**: 이 스킬은 두 종류의 "재색인"을 한다.
> - **그래프 재색인**(여기 ①.5) — codebase-memory-mcp **지식그래프**(`index_repository`/`detect_changes`). 코드 인텔리전스 substrate.
> - **도메인 재색인**(아래 "재색인만 모드") — `domain-sync` 가 만드는 **`docs/domain/` 원장·`tables/`**. 문서 색인.
> 이름은 같아도 층위가 다르다. "재색인만 모드"는 원래 **도메인 재색인**(LLM 저작 스킵)을 뜻하지만, ①.5 의 **그래프 증분 재색인**도 함께 수행한다(둘 다 비용이 낮고 최신 상태를 맞춘다).

### ② domain-sync (초회)

`.claude/docs/domain/` 아래 모듈 페이지 `## 카탈로그` 표·`tables/` 역색인·`index.md`(있으면) 원장 블록을 결정론으로 갱신한다. "의미" 칸과 블록 밖 본문(`## 핵심`·`## 흐름`·요약 등)은 재실행해도 그대로 보존된다. 이 실행이 콘솔에 찍는 요약(`domain-sync: +N ~N =N pages, 의미 빈칸 M, 후보 K`)을 다음 판단에 그대로 쓴다.

**코드 변경 없음 → fan-out 스킵**: 이 요약이 `+0 ~0`(생성·갱신된 페이지가 0)이고 `의미 빈칸`도 `0`이면, 지난 실행 이후 카탈로그에 영향을 준 소스 변경이 전혀 없었다는 뜻이다 — ③을 건너뛰고 바로 ④·⑤로 넘어간다(LLM 비용 0).

### ③ fan-out 대상 추리기 (무변경이 아닐 때)

②가 갱신한 `index.md`의 `<!-- catalog-ledger -->` 표(`| 모듈(경로) | 카탈로그 행 | 의미 채움 | 테이블 수 |`)를 읽어 "의미 채움"이 `분자/분모`로 분자<분모인 모듈, 즉 **의미 빈칸이 남은 모듈만** fan-out 대상으로 추린다. 이 표는 ②가 매번 자동 갱신하므로 따로 diff 파일을 유지할 필요가 없다. fan-out 자체(서브에이전트 배치·프롬프트 구성·의미 저작 규칙)는 `.claude/docs/domain-synthesis.md` ④ 절차 그대로 따른다.

전체 모드는 이 필터를 쓰지 않는다 — 아래 "전체 모드" 참고.

### ④ domain-sync (재실행)

③의 fan-out 반환(의미 칸 값·`## 핵심`·`## 흐름`·frontmatter `domain:`)을 모듈 페이지에 먼저 반영한 뒤 다시 실행해 `index.md`·`domains/*.md`의 도메인→테이블 집계를 완성한다. ③을 건너뛴 경우(무변경)에도 이 단계는 그대로 실행한다(멱등 — 바뀐 게 없으면 `=`로만 끝난다).

### ⑤ 자동 게이트

아래 "자동 게이트" 절 그대로 `we-adp verify-domain-rules <root>`를 실행하고 통과할 때까지 재검증한다.

### ⑥ 검수 (1회·자동)

게이트 통과 뒤 `.claude/docs/domain-synthesis.md`의 "⑦ 검수" 절차를 그대로 1회 수행한다(분류 정합·빈칸 재도전·잘린 설명·고아 도메인 + 정착 재실행 1회, 전부 자동 적용 + 요약 보고). 절차 본문은 여기 다시 적지 않는다 — 단일 출처를 따른다. **재색인만 모드에서도 ⑥은 수행한다**(fan-out 은 건너뛰어도 기존 페이지의 잘린 설명·고아 도메인·taxonomy 겹침은 다듬을 값이 있다).

## 전체 모드

공통 절차 ①~⑥을 그대로 수행하되, ②가 "코드 변경 없음"으로 판정하지 않는 한 ③에서 의미 빈칸 필터를 쓰지 않고 **도메인 티어로 판정된 모듈 전부**를 fan-out 대상으로 삼는다(티어 판정 기준은 `.claude/docs/domain-synthesis.md` 참고 — 여기서 다시 적지 않는다). 모듈 구조 개편 등으로 티어 판정 자체를 다시 확인하고 싶을 때 이 모드를 쓴다.

## 증분 모드 (기본)

공통 절차 ①~⑥을 그대로 수행한다. ③에서 의미 빈칸이 남은 모듈만 골라 fan-out 하므로(위 "③ fan-out 대상 추리기" 참고) 평소 최신화는 이 모드로 충분하다.

## 재색인만 모드

공통 절차 중 **①·②(결정론 스캔+병합)는 그대로 실행한다** — 비용이 없고, 카탈로그·`tables/`·원장을 최신 상태로 맞춰 준다. 다만 **③(fan-out)은 의미 빈칸 유무와 무관하게 무조건 건너뛴다** — LLM 재저작을 하지 않는다. 페이지를 손으로 고친 뒤 색인·집계 표만 맞추고 싶을 때, 또는 소스 재분석 결과만 최신화하고 싶을 때 쓴다. ④·⑤·⑥은 그대로 수행한다(③을 건너뛰었으므로 ④는 새로 채울 의미가 없어 대체로 무변경으로 끝난다). v1 의 "소스를 아예 안 보는" 재색인은 의도적으로 폐기했다 — 결정론 스캔(①②)은 LLM 비용 없이 항상 공짜로 돌 수 있기 때문이다.

## v1 이행 (구버전 산출물 마이그레이션)

모듈 페이지에 `<!-- catalog:begin -->` 블록이 없으면 `we-init`이 v1 절차(스켈레톤만 읽고 LLM이 표까지 직접 다 작성하던 구버전)로 만든 산출물이다. 특별한 분기 없이 위 공통 절차를 그대로 돈다 — ②(domain-sync 초회)가 마커가 없는 페이지를 만나면 파일 끝에 새 `## 카탈로그` 블록을 삽입만 하고, 기존 `## 핵심`·`## 흐름`·요약 등 본문은 그대로 남는다(덮어쓰지 않는다).

`taxonomy.md`가 없으면(v1 번들은 대부분 없다) 다음을 추가로 수행한다. **확정 시점 주의**: v1 페이지는 카탈로그 블록이 없어 ② 직후 의미 빈칸이 많고, 그래서 ③ fan-out 이 크게 돌며 새 `domainName` 제안을 들고 돌아온다 — 기존 값만으로 fan-out **전에** taxonomy 를 확정해 버리면 fan-out 이 부여한 새 `domain:` 값이 ⑤ 검증에서 바로 깨진다. 따라서 taxonomy 확정은 **③ fan-out 반환까지 받은 뒤, ④ 재sync·⑤ verify 앞**에 한다:

1. 기존 `modules/*.md`·`domains/*.md`의 frontmatter `domain:` 값과 `domains/` 아래 파일명, 그리고 **③ fan-out 반환의 `domainName` 제안**을 합쳐 domain 목록 초안을 만든다.
2. 초안을 사용자에게 보여주고 확정받는다(중복 통합·이름 정리 포함) — `.claude/docs/domain-synthesis.md`의 "taxonomy.md" 절이 정의한 것과 같은 확정 방식이다.
3. 확정된 목록을 그 절이 정의한 형식(`## domain` / `## type`)대로 `taxonomy.md`로 저작한 뒤 ④(재sync)·⑤(verify)를 진행한다.

`taxonomy.md`가 생기면 그 다음 ⑤(`verify-domain-rules`)부터 taxonomy 축 검증이 켜진다(파일이 없는 동안은 건너뛴다).

## 로직 공유 (복제 금지)

티어 판정 기준·fan-out 서브에이전트 프롬프트 구성·저작 규칙(등급·출처태그·인용 정밀도·인용 경로 형식·비밀 안전수칙)·페이지 형식(frontmatter+본문)·taxonomy·무손실 매핑·인용 규칙·엔진 소유 블록 목록은 전부 `.claude/docs/domain-synthesis.md`에 정의돼 있다. 이 스킬은 그 절차를 **어떤 모드에서 fan-out을 얼마나(전체/빈칸만/전혀 안 함) 돌릴지**만 정하고, 절차 자체의 세부 규칙은 그대로 참조한다 — 이 문서 안에 다시 옮겨 적지 않는다.

## 사용자 편집 보존

`## 카탈로그` 표·`index.md`의 원장·도메인→테이블 블록·`domains/*.md`의 테이블 블록·`tables/` 전체는 `domain-sync`가 결정론으로 생성·병합하는 엔진 소유 영역이다(재실행해도 사람이 손댄 블록 밖 본문은 지워지지 않는다). fan-out 반환을 모듈 페이지에 반영할 때도 의미 칸 채우기·`## 핵심`·`## 흐름` 추가는 그 페이지 안의 다른 본문(요약·`## 관련` 등)을 건드리지 않는 삽입/치환으로 한다 — 페이지 전체를 통째로 새로 쓰지 않는다. 부득이 페이지 전체를 새로 쓸 수밖에 없을 때(예: 형식이 크게 어긋난 v1 페이지를 손으로 정리해야 할 때)만 교체 전 `<원본경로>.bak`으로 백업한다.

## 자동 게이트

합성(또는 재동기화)이 끝나면 항상 다음을 실행한다:

```bash
we-adp verify-domain-rules {root}
```

broken(인용·taxonomy·백링크 문제)이 있으면 해당 항목의 근거를 다시 확인해 고치고, 통과할 때까지 재검증한다. 의미 빈칸은 정보성 집계라 통과를 막지 않는다 — 통과(broken 0)해야 이 스킬의 작업을 완료로 본다.
