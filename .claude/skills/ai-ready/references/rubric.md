# ai-ready 루브릭 — 채점 단일 출처

> 채점: 영역별 1~5점. 표기: ×4 환산 (영역 20점, 총 100점). **모든 점수에 transcript 근거 인용 필수 — 근거 없는 점수 금지.**

## 영역별 기준

### 1. 워크플로우 활용 (workflow)

| 점수 | 기준 (관측 가능한 행동) |
| --- | --- |
| 1 | 스킬 호출 0건 — 모든 작업을 즉흥 지시로 진행 |
| 2 | git 등 보조 스킬만 사용, 개발 흐름은 즉흥 지시 |
| 3 | 작업 성격에 맞는 스킬 선택 사용 (develop, code-review 등) |
| 4 | 정식 파이프라인(dev-interview→dev-plan→develop→code-review)을 주요 과업에 적용 |
| 5 | 4 + 서브에이전트 활용 + pack 핸드오프까지 — 세션 전 주기 워크플로우화 |

### 2. 지시 품질 (direction)

| 점수 | 기준 |
| --- | --- |
| 1 | 모호한 지시 위주, 평균 4회 이상 재교정 |
| 2 | 평균 3회 내외 교정, 목표·제약 누락 빈번 |
| 3 | 목표·제약 포함 지시, 평균 1~2회 교정 |
| 4 | 1회 완결 비율 50% 이상, 사후 번복 거의 없음 |
| 5 | 1회 완결 비율 70% 이상, 완료 기준까지 명시한 지시 |

### 3. 위임 수준 — 노코딩 (delegation)

| 점수 | 기준 |
| --- | --- |
| 1 | 코드 대부분 수동 작성·수정 (세션 외 git diff 다수) |
| 2 | 생성은 위임하나 수정 절반 이상 수동 |
| 3 | 생성 위임, 수정에 수동 개입 빈번 (세션 외 diff 2~3건) |
| 4 | 수동 개입 1건 이하, 사람은 방향·검증 위주 |
| 5 | 코드 변경 100% Claude 경유 — 세션 외 diff 0건 |

### 4. 문제해결 협업 (problem)

| 점수 | 기준 |
| --- | --- |
| 1 | 막히면 세션 포기 또는 전부 수동 해결 |
| 2 | 에러 메시지 전달 수준, 분석은 수동 |
| 3 | 에러를 Claude와 함께 분석·해결 |
| 4 | 데이터(로그·재현 조건)를 제공하며 가설 검증 위임 |
| 5 | 체계적 디버깅 위임, 근본 원인까지 추적해 세션 안에서 해결 완료 |

### 5. 검증·규정 준수 (verify)

| 점수 | 기준 |
| --- | --- |
| 1 | 커밋 전 code-review·테스트 전부 생략 |
| 2 | code-review 절반 미만 수행 |
| 3 | code-review 수행, 일부 누락 또는 테스트 미실행 |
| 4 | 전 커밋 code-review + 테스트 실행 일부 |
| 5 | 리뷰+테스트+브랜치 전략 전부 준수 |

## 가이드라인 구간 (총점 해석)

| 구간 | 단계 | 의미 |
| --- | --- | --- |
| 0~39 | 도입 | 수동 작업 위주. 스킬·파이프라인 온보딩 필요 |
| 40~59 | 적응 | 부분 활용. 코칭 포인트 도출 구간 |
| 60~79 | **정착** | **팀 기대 수준 — 기준선.** 전 영역 평균 3점 이상 |
| 80~100 | 숙련 | 파이프라인 풀 활용 + 높은 위임. 사례 전파자 역할 |

## 운영 가이드

- 단기 목표(도입 1~2개월): 60점. 초기 40~50점대는 정상 (변별력의 증거)
- 이후 목표: 80점
- 절대점수보다 전주 대비 추이를 우선 — 리포트도 추이를 먼저 보여준다
- 2~3주 누적 후 실분포 기준으로 구간 경계를 팀 합의로 보정 (이 파일만 수정)
- 이 리포트는 자기 발표 자료다 — 인사평가·랭킹 용도 금지
