# /domain-ask <질문>

`.claude/docs/domain/index.md`(진입점)와 그 아래 페이지들을 **읽기 전용으로** 훑어 질문에 답한다. 페이지를 만들거나 고치는 건 이 스킬의 일이 아니다 — 그건 `domain-update`(또는 최초 생산자 `we-init`) 소관이다. 이 스킬은 **사람이 명령으로 부르는 수동 질의**다. 하네스가 작업 중 자동으로 도메인 문서를 참고하는 자동배선과는 다르다 — 자동배선은 각 에이전트가 필요할 때 알아서 하고, `/domain-ask`는 사람이 궁금할 때 직접 부른다.

## 사전 조건

- `.claude/docs/domain/index.md`가 있어야 한다. 없으면 "도메인 분석 번들이 아직 없습니다. 먼저 `we-init`을 실행해 주세요."라 안내하고 중단한다.

## 질문 유형에 따라 조회 경로가 다르다

- **테이블·라우트·진입점처럼 구조를 묻는 질문**("이 테이블 누가 쓰나요", "이 URL 처리하는 코드가 어디죠", "이 API 진입점이 어느 테이블을 만지나요")은 **역색인·카탈로그 표에서 결정론으로** 답이 나온다 — 의미 해석이 필요 없다.
- **업무 규칙·흐름을 묻는 질문**("왜 이렇게 처리하나요", "이 처리의 업무 규칙이 뭔가요")은 카탈로그 표의 **"의미" 칸**과 모듈 페이지 **`## 핵심`**(룰)·**`## 흐름`**을 인용해 답한다 — 이건 LLM이 저작한 영역이다.

## 절차

1. **진입** — 질문 유형에 따라 시작 지점이 다르다.
   - 테이블명을 알고 있으면 `.claude/docs/domain/tables/catalog.md`(테이블 → 어느 모듈·몇 개 진입점이 쓰는지 역색인, 300행 넘으면 `tables/catalog-2.md`…로 이어진다)를 먼저 연다.
   - URL·라우트를 알고 있으면 `.claude/docs/domain/modules/` 를 라우트 문자열로 Grep 한다 — 모듈 카탈로그 표의 "라우트/트리거" 컬럼에 걸리는 페이지가 담당 모듈이다.
   - 그 밖의 질문(도메인 개념·업무 흐름·모듈 전반)은 `.claude/docs/domain/index.md`를 연다 — product×domain 매트릭스, 페이지 목록, 소스맵, 모듈 커버리지 원장이 여기 있다.
2. **좁히기** — 질문의 키워드(모듈 경로·도메인명·업무어·테이블명·라우트)를 1의 색인·매트릭스·페이지 목록과 대조해 **관련 있어 보이는 페이지만** 추린다. 확신이 안 서면 후보를 넉넉히 잡되(모자라서 근거를 놓치는 것보다 낫다), 색인 자체가 "전부 열지 않고 좁히기 위한" 산출물이라는 목적을 잊지 않는다 — 관계없는 페이지까지 습관적으로 다 열지 않는다.
3. **열람** — 2에서 추린 `modules/<slug>.md`(그 안의 `## 카탈로그` 표 포함)·`domains/<slug>.md`·`common.md`·`tables/*.md`만 연다. 그 밖의 페이지, 그 밖의 소스 코드는 열지 않는다(질의 범위는 이미 만들어진 도메인 문서로 한정 — 이 스킬은 재분석을 하지 않는다).
4. **답변** — 연 페이지의 내용만 근거로 답한다. **테이블·라우트·진입점 질문은 역색인·카탈로그 표에서 결정론으로 답을 찾고, 업무 의미는 의미 칸·`## 핵심` 룰을 인용한다.** 답변마다 어느 페이지의 어느 항목을 봤는지 **인용**한다(예: 페이지 경로 + 룰/흐름 서술 일부, 페이지에 근거 `파일:줄`이 있으면 그것도 같이 밝힌다). 연 페이지들 어디에도 답을 뒷받침할 내용이 없으면 **추측하지 말고 "근거 없음"이라 답한다** — 인접한 다른 페이지를 열어 더 찾아볼지 사용자에게 물어봐도 된다.

## 답변 형식

- 결론 먼저, 한두 줄로 쉽게.
- 그 아래 인용: 어떤 페이지(경로)의 어떤 서술을 근거로 삼았는지.
- 여러 페이지에 걸친 답이면 페이지별로 나눠 인용한다.
- 근거가 없거나 부족하면 "근거 없음" 또는 "확인 필요"라 명시하고, 추측이나 일반 지식으로 채워 넣지 않는다.

## 하지 않는 것

- 페이지·색인 파일을 새로 쓰거나 고치지 않는다(수정은 `domain-update`).
- 소스 코드를 다시 읽어 재분석하지 않는다(질의는 이미 만들어진 문서 범위 안에서만).
- 관련 없는 페이지까지 전부 열어 훑지 않는다(색인으로 좁히는 게 이 스킬의 핵심).
