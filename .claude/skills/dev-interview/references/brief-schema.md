## 섹션별 작성 주체 (단일 출처)

자율 선탐색 3 sub-agent 가 자기 토픽 섹션의 **초안**을 함께 반환하고, 메인이 나머지 섹션과 병합·교차 판단을 맡는다. 탐색 결과를 리포트로 받아 메인이 브리프 섹션으로 다시 옮겨 쓰면 병렬로 얻은 것을 직렬로 한 번 더 쓰는 셈이라, 초안을 스키마 모양으로 바로 받는다.

| 섹션 | 작성 주체 | 근거 |
|---|---|---|
| §3-4 영향 테이블, §5 코드값 사전 | `db-meta-manager` | 테이블·컬럼 메타와 `column_comment` 를 그 에이전트만 조회한다 |
| §4 업무↔코드 매핑, §7 화면 맵, §10 재사용 자산 | `code-investigator` | 엔드포인트·템플릿·공통 자산 탐색 결과가 그대로 이 세 섹션이다 |
| §6 외부 통신 보안 스펙, §8-1 보안 | `security-auditor` | 암호화·서명·SSO·PII 반출 판정이 이 에이전트 산출이다 |
| §1 문서 메타, §2 시스템 결정, §3-1~3-3 스코프, §8-2~8-4, §9 미결사항, §11 구현 순서 | 메인 (dev-interview) | 요구사항 해석·스코프 결정·교차 판단이 필요해 한 토픽에 속하지 않는다 |

**규칙:**
- 초안 제목은 **이 스키마의 제목 그대로** 쓴다(`## 5. 코드값 사전`). 라벨이 스키마와 같아야 병합이 결정론이 된다.
- 초안은 **근거 있는 사실만.** 모르는 항목은 비우고 갭으로 신고한다 — 초안의 추측은 브리프를 통과해 계획서까지 간다.
- **섹션 간 모순은 초안 작성자가 못 본다.** 각 에이전트는 자기 섹션만 봤으므로 §4↔§5 불일치, §6↔§4 불일치는 메인의 교차 점검 단계가 유일한 검사 지점이다.
- 담당 에이전트가 skip 됐으면 메인이 그 섹션을 쓰고, skip 사실을 §9 에 남긴다.
- 병합 결과는 아래 「Stage 1 형식 게이트」와 `scripts/validate-brief.ps1` 이 검사한다 — 라벨이 틀어진 병합은 조용히 통과하지 않는다.

## 스키마 본문

```markdown
# 개발 브리프 — {과업번호} {주제}

## 1. 문서 메타
| 항목 | 값 |
|------|-----|
| 기획서 파일 | {경로 또는 "없음 (인터뷰만)"} |
| 기획서 버전 | {버전 또는 "-"} |
| 기획서 품질 등급 | {자율 평가 — HIGH/MEDIUM/LOW 또는 "해당 없음"} |
| 인터뷰 일자 | {yyyy-MM-dd} |
| 과업번호 | {n} |
| 작업 브랜치 | {브랜치 또는 "미정"} |
| 제안 개발 기간 | {n 영업일} |

## 2. 시스템 결정
| 항목 | 결정 | 근거 |
|------|------|------|
| 개발 유형 | 신규 | 기존 확장 (brownfield) | {근거} |
| 프로젝트 유형 | web-api | web-fullstack | batch | daemon | library | ... | {근거} |
| 프로젝트명 | {이름} | {명명 규칙} |
| 베이스 패키지 | {{config.baseNamespacePattern}} (예: com.acme.platform.{xxx}) | 공통 규칙 |
| 배포 포맷 | JAR | WAR | {근거} |
| 빌드 | 빌드 도구 {단일|멀티모듈} | {근거} |

## 3. 타겟 스코프
### 3-1. Primary (쓰기 대상)
### 3-2. Related — 호출 대상 (읽기·참조)
### 3-3. Related — 패턴 참조
### 3-4. 영향 테이블 (신규 포함)

## 4. 업무↔코드 매핑
### 4-1. 기획서 번호 체계 → 내부 API URI
### 4-2. 기획서 단계 → 엔드포인트 (제안)
### 4-3. 기획서 메뉴 → 컨트롤러 (제안)
### 4-4. 기획서 용어 ↔ DB 컬럼

## 5. 코드값 사전
### 5-1. 상태·구분 코드 (DB column_comment 자동 수집)
### 5-2. 기획서 표현 → 코드 매핑 (역방향)

## 6. 외부 통신 보안 스펙
(API 호출 헤더/암호화/서명, SSO, 세션 등 — 없으면 "해당 없음")

## 7. 화면 맵
(템플릿/JS 경로 트리 — 없으면 "해당 없음")

## 8. 특수 요구사항
### 8-1. 보안 (기획서 미명시 보안 요구)
### 8-2. 인프라 (프로젝트 유형별 기본 탑재)
### 8-3. UI 프레임워크
### 8-4. 알림/이벤트 연계

## 9. 미결사항 (Open Questions)
(담당자·별첨문서 확인 필요 항목, 또는 인터뷰 중 보류된 갭)

## 10. 재사용 가능 자산
### 10-1. 라이브러리 ({{config.commonUtilsArtifact}} 등 — project.yaml `commonUtilsArtifact` 단일 출처)
### 10-2. 참조 코드 패턴
### 10-3. 공통 모듈·설정

## 11. 구현 순서 제안
(의존성 기반 순번, Phase 단위 권장)

---

**선탐색 시간**: ~분
**인터뷰 라운드**: n회 (1:1 대화형)
**자동 매핑 커버리지**: ~%
**Codex 검토 등급**: GREEN | YELLOW (메모: ...) | RED (escalate)
```
