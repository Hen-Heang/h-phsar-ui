## 이것은 분량 상한이 아니다

지우는 대상은 **연결어·수식·재서술**이고, 남기는 대상은 **숫자·경로·식별자·판정·근거 좌표**다. 줄일 것이 없으면 줄이지 않는다.

`phase-doc-schema.md` 「재서술 금지」와 역할이 다르다:

| 계약 | 무엇을 정하나 |
|---|---|
| 재서술 금지 | **무엇을 넣지 않나** (다른 문서가 소유한 내용) |
| 문체 계약(본 파일) | **남은 것을 어떻게 쓰나** (문장 형태) |

둘 다 행수 상한이 아니다. 6행을 지킨 문서가 길면 페이즈가 큰 것이고, 전보체로 쓴 문서가 길면 사실이 많은 것이다.

## 규칙

1. **명사구 종결.** 체언·명사구로 끝낸다. 서술 종결어미(`~한다`·`~이다`·`~합니다`)는 판정 1줄에만 허용 — 판정 = "조치 대상", "회귀 위험", "해당 없음" 같은 결론.
2. **1항목 1줄.** 산문 2줄 연속 금지(= 문단 금지). 표 셀에 문장 2개 금지.
3. **근거는 좌표로.** `파일:줄` 또는 `브리프 §N`. 근거를 문장으로 풀지 않는다.
4. **빈 섹션은 2줄.** `해당 없음 — {사유 명사구}` + 필요 시 `근거: {좌표}` 1줄.
5. **열거는 가운뎃점.** `A·B·C`. "그리고"·"및"·쉼표 나열 대신.

## 삭제 대상 어휘

접속·인과 연결어(`따라서`·`그러므로`·`왜냐하면`·`즉`·`이에 따라`), 도입어(`참고로`·`우선`·`먼저`), 설명 상투구(`~하는 이유는`·`~라는 점에서`·`~임을 알 수 있다`), 정도 수식어(`매우`·`상당히`·`전반적으로`), 배경 재서술(요구사항·업무 흐름을 다시 쓴 문장 — 소유자는 브리프).

## Before / After

**빈 섹션 (브리프 §6)**

```markdown
<!-- before — 435자 문단 -->
해당 없음 — 이 잡은 외부 API 호출·SSO·세션을 쓰지 않는다. 제공 파일은 로컬 디렉터리에
`.tmp` 로 기록한 뒤 `renameTo` 로 확정하고 외부 수거 프로세스가 폴링하는 pull 방식이다
(`FileWriter.java:49-53`). 따라서 전송 구간 암호화나 서명 요구가 발생하지 않으며 ...

<!-- after -->
해당 없음 — 외부 API·SSO·세션 미사용.
근거: FileWriter.java:49-53 (로컬 .tmp → renameTo, 외부 폴링 pull)
```

**순서 열거 (브리프 §11)**

```markdown
<!-- before — 항목마다 1,000자 한 줄 -->
1. Phase 1 — 특성화 안전망 (변경군·불변군 분리): 수정 작업이므로 PRESERVE 게이트를 먼저
   세운다. 현재 동작을 있는 그대로 박제하되 두 군으로 명시 분리한다. 변경군은 ...

<!-- after -->
| # | Phase | 하는 일 | 근거 |
|---|---|---|---|
| 1 | 특성화 안전망 | 변경군/불변군 분리, PRESERVE 게이트 | 수정 작업 |
| 2 | 경로 평면화 | outputDirectory() 세그먼트 제거 | FileWriter.java:30 |
| 3 | 경합 보정 | mkdirs() 실패 판정 멱등화 | 공유 디렉터리 |
```

두 예시 모두 **사실은 그대로**다 — 사라진 것은 접속사·재서술·수식뿐.
