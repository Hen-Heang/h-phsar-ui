> **단일 출처**: 구현 에이전트의 5단계 보고 형식·보고 영역 한정 규칙은 본 파일이 마스터. 호출 에이전트 본문에 템플릿 인라인 복사 금지 — 본 파일만 수정하면 모든 구현 에이전트에 자동 반영된다.

---

## 보고 영역 한정 (모든 구현 에이전트 공통)

5단계 보고는 아래 4가지까지만 포함한다:

1. 생성/수정 파일 목록
2. 자체 점검 결과 (스택 고유 항목 — 호출 에이전트 본문에 명시)
3. `{{config.test.command}}` 실행 결과 인용 (GREEN/RED)
4. 미처리 항목 (해당 시)

**금지 어휘**: _"qa-test 실행하시겠어요?"_ / _"커밋해도 되나요?"_ / _"코드 리뷰 받으세요"_ / _"다음 단계로 진행할까요?"_ 등 검수 안내·다음 단계 어휘는 출력하지 않는다. qa-test·커밋·리뷰는 사용자가 별도 명시 호출로 트리거하는 영역이며, 페이즈 종료 후 자연 멈춤은 메인 Claude 가 관리한다 (구현 에이전트의 책임 아님).

> **DoD 판정 주체**: dev-plan 페이즈 문서 §9 완료의 정의(DoD) 표의 대조·판정은 develop 수렴 루프가 담당한다. 구현 에이전트는 DoD 표를 자체 판정·보고하지 않는다.

---

## 5단계 보고 템플릿

```markdown
## {영역명} 생성 완료

### 생성된 파일

| # | 파일 | 상태 |
| --- | --- | --- |
| 1 | {경로} | 생성 |
| ... | ... | ... |

### 기존 파일 수정 (해당 시)

| # | 파일 | 변경 내용 |
| --- | --- | --- |
| 1 | {경로} | {변경 설명} |

### 자체 점검 결과

> 스택 고유 자체 점검 항목(호출 에이전트 본문 정의)을 한 표로 통합. 통과 여부 또는 수정 전/후.

| 점검 항목 | 결과 | 수정 사항 (해당 시) |
| --- | --- | --- |
| {항목} | Y | — |
| ... | ... | ... |

### `{{config.test.command}}` 실행 결과 (페이즈 종료 신호)

**실행 명령**: `{{config.test.command}}`
**결과**: GREEN / RED

```
{테스트 결과 요약 라인 그대로 인용}
```

**RED 시 보고 모드 (예시)**:

| 실패 테스트 | 실패 사유 | 의심 위치 (본 에이전트 생성 코드) |
| --- | --- | --- |
| `{실패한 테스트 이름}` | {런타임 오류 요약} at `{파일}:{줄}` | `{함수/메서드}` (예: `OrderService` 생성 경로) |

> RED 발생 시 본 에이전트는 다음 단계 진행하지 않는다 — 메인 Claude 가 사용자에게 결과 보고 후 발화 대기 (`dev-gate.md` brake 참조).

### 미처리 항목 (해당 시)

> 메인 Claude 가 다음 페이즈로 디스패치한다 — 본 에이전트는 자동 호출하지 않는다.

| # | 파일 | 대상 에이전트 |
| --- | --- | --- |
| 1 | {경로} | {대상 에이전트명} |
```
