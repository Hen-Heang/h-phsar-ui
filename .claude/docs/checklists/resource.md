# Resource — 자원 관리 체크리스트

> 성능 경로의 느린 작업 차단, 희소 자원(연결 등)의 올바른 범위 한정, 비동기 작업의 누적 상한, 리소스 사이즈 산정에 관한 원칙.
> 언어·도메인에 무관한 범용 원칙만 다룬다. 구체적 구현 예시는 lang 파일 참조.

---

## RES-01 — 동기 핫 경로에 느린 작업 금지

**원칙:**
동기 요청 처리 경로(사용자 요청에 직접 응답하는 흐름)에 느린 연산(대용량 집계, 풀스캔, 무인덱스 조회 등)을 배치하지 않는다. 대신 누적 결과를 별도로 캐싱하거나, 적절한 인덱스를 갖추고, 대용량 테이블 접근 시 실행 계획을 검토한다. 느린 연산이 요청 처리 경로에 있으면 외부 타임아웃 → 재시도 폭주로 이어질 수 있다.

**검증 질문:**
- 동기 요청 경로에서 매 요청마다 대용량 집계나 풀스캔이 발생하는가?
- 자주 조회하는 누적 값은 별도 저장소에 캐싱하여 갱신하고 있는가?
- 대용량 테이블 접근 쿼리에 적절한 인덱스가 있고 실행 계획이 검토되었는가?
- 느린 연산이 외부 타임아웃·재시도 폭주를 유발할 위험이 없는가?

**심각도:** Critical

## RES-02 — 희소 자원을 외부 호출에 묶지 않기

**원칙:**
데이터베이스 연결 등 개수가 제한된 자원(연결 풀)을 외부 시스템 호출과 같은 장기 대기 작업과 함께 묶지 않는다. 트랜잭션 경계는 데이터베이스 작업 전용으로 한정하고, 외부 호출은 트랜잭션 밖에서 실행하거나 커밋 후 비동기로 발사한다. 외부 호출이 지연되면 연결이 장기 점유되어 전체 서비스가 중단될 수 있다.

**검증 질문:**
- 트랜잭션 경계 안에서 외부 시스템 호출을 하지 않는가?
- 트랜잭션 범위가 데이터베이스 작업만으로 한정되어 있는가?
- 외부 호출이 지연되어도 연결 풀이 고갈되지 않는 구조인가?
- 외부 호출에 합리적인 연결 타임아웃·읽기 타임아웃이 설정되어 있는가?

**심각도:** Critical

## RES-03 — 비동기 누적 작업 상한·만료 처리

**원칙:**
비동기 처리 큐나 상태 테이블에 실패 건이 무한히 쌓이지 않도록 재시도 횟수 상한, 만료 기간, 미처리 건 정리 배치를 갖춰야 한다. 상한 없이 누적되면 메모리 고갈이나 큐 처리 지연으로 이어진다. 누적량이 임계치를 초과하면 알람을 발송해야 한다.

**검증 질문:**
- 비동기 처리 실패 건에 재시도 횟수 상한이 있는가?
- 오래된 미처리 건을 별도로 이관하거나 정리하는 절차가 있는가?
- 미처리 건이 임계치를 초과했을 때 알람이 발송되는가?
- 실패 건이 무한히 누적되어 자원을 소진하는 구조가 없는가?

**심각도:** Warning

## RES-04 — 리소스 사이즈 근거 기반 산정

**원칙:**
메모리, 연결 풀, 스레드 풀 등 리소스 크기를 기본값 그대로 사용하지 않는다. 예상 최대 트래픽, 동시 접속 수, 부하 시나리오 테스트 결과를 근거로 산정하고 문서화한다. 근거 없는 기본값 사용은 예측할 수 없는 자원 고갈로 이어진다.

**검증 질문:**
- 리소스 크기(메모리, 연결 풀, 스레드 풀 등) 설정에 산정 근거가 명시되어 있는가?
- 기본값을 그대로 사용하는 항목이 없는가?
- 부하 시나리오 테스트(메모리·자원 추이)를 수행했는가?
- 여러 인스턴스가 자원을 공유할 경우 인스턴스별 분배가 명시되어 있는가?

**심각도:** Warning
