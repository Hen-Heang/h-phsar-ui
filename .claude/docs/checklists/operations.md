# Operations — 운영 안정성 체크리스트

> 배포 시 의존성 동기화, 비동기·배치·외부 연동의 실패 알람 정의에 관한 원칙.
> 언어·도메인에 무관한 범용 원칙만 다룬다. 구체적 구현 예시는 lang 파일 참조.

---

## OPS-01 — 배포 시 의존성·설정 동기화

**원칙:**
새로운 라이브러리나 공통 설정을 추가할 때 배포 대상 모든 서버에 반영해야 한다. 누락 시 런타임에 예기치 않게 실패하지 않도록, 의존성 불일치를 부팅 시점에 즉시 감지하고 중단(fail-fast)하는 구조를 갖춰야 한다.

**검증 질문:**
- 신규 의존성 추가 시 배포 대상 서버 목록과 동기화 절차가 명시되어 있는가?
- 의존성 매니페스트(의존성 선언 파일)가 변경된 경우 모든 배포 환경에 반영되었는가?
- 의존성 불일치가 런타임이 아닌 부팅 단계에서 즉시 감지되는가?

**심각도:** Warning

## OPS-02 — 비동기·배치·외부 연동 실패 임계치 알람 정의

**원칙:**
비동기 처리, 배치 작업, 외부 시스템 연동을 추가하거나 수정할 때는 실패 임계치와 알람을 함께 정의해야 한다. 실패를 자동으로 인지하지 못하면 문제가 장시간 방치되어 대규모 장애로 이어진다. 알람은 적시성 채널(메신저, SMS 등)로 전달되어야 한다.

**검증 질문:**
- 신규·수정 배치, 비동기 처리, 외부 연동에 실패 임계치 알람이 정의되어 있는가?
- 실패율, 타임아웃 발생률, 미처리 건수가 모니터링 대시보드에 등록되어 있는가?
- 알람이 담당자에게 적시에 전달되는 채널이 지정되어 있는가?
- 알람 임계치가 도메인·서비스 특성에 맞게 설정되어 있는가?

**심각도:** Warning
