# Data Access — 데이터 접근 안전 체크리스트

> 외부 입력이 쿼리 범위를 결정하는 위험 차단, 느린 쿼리 관측 도구 운영에 관한 원칙.
> 언어·도메인에 무관한 범용 원칙만 다룬다. 구체적 구현 예시는 lang 파일 참조.

---

## DATA-01 — 신뢰할 수 없는 입력의 쿼리 범위 통제

**원칙:**
외부에서 받은 입력값이 쿼리의 조회 범위(카디널리티)를 직접 결정하게 하지 않는다. 입력 기반 범위를 허용할 경우 애플리케이션 레이어에서 사전 검증으로 상한을 제한하고, 저장소 레이어에서도 이중으로 상한을 적용하여 방어한다.

**검증 질문:**
- 외부 입력이 쿼리 조회 범위를 직접 결정하는 경우가 있는가?
- 입력 기반 범위에 대해 애플리케이션 레이어에서 상한을 검증하는가?
- 저장소 레이어에서도 범위 상한을 이중으로 적용하는가?
- 카디널리티 폭발로 인한 데이터베이스 부하가 발생하지 않도록 보장되는가?

**심각도:** Critical

## DATA-02 — 느린 쿼리 관측 도구 상시 운영

**원칙:**
운영 환경에서 느린 쿼리를 자동으로 탐지하고 기록하는 도구를 항상 활성화한다. 느린 쿼리를 사후가 아닌 실시간으로 인지해야 성능 장애를 예방할 수 있다. 정기적으로 느린 쿼리 보고서를 검토하고 개선 조치를 취한다.

**검증 질문:**
- 운영 환경에서 느린 쿼리를 자동으로 기록하는 설정이 활성화되어 있는가?
- 느린 쿼리 통계 및 이력을 주기적으로 검토하는 절차가 있는가?
- 느린 쿼리 발생 시 실시간 또는 주기적으로 인지할 수 있는 체계가 있는가?

**심각도:** Warning
